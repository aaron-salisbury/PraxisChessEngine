# Modernization Roadmap

This roadmap is temporary planning for the `modernize` branch. The legacy solution remains available as reference while the replacement engine is developed under `src`.

| Step | Goal | Status | Summary |
| --- | --- | --- | --- |
| 1 | Establish chess core | Complete | Define compact engine-owned representations for squares, pieces, colors, moves, positions, castling rights, en passant state, clocks, and FEN import/export. Keep the core independent of UCI, persistence, HTTP, and UI concerns. |
| 2 | Implement legal move generation | Complete | Build pseudo-legal move generation, attack detection, make/unmake move support, and legal-move filtering. Cover castling, promotion, en passant, check, checkmate, stalemate, repetition-relevant state, and the fifty-move clock with strong unit tests and perft validation. |
| 3 | Add search foundation | Complete | Implement a deterministic negamax/alpha-beta search over legal positions with iterative deepening, quiescence search, terminal scoring, cancellation, and search limits. Return a structured search result rather than protocol text. |
| 4 | Add position evaluation | Complete | Introduce a simple, testable static evaluation function starting with material and piece-square/activity terms. Evolve heuristics only after search correctness and benchmarking are in place. |
| 5 | Add engine session/application layer | Complete | Create a focused engine/session service that owns the current position and coordinates position setup, move application, search requests, cancellation, new-game reset, and engine options. This is the protocol-independent API consumed by adapters. |
| 6 | Add replaceable protocol boundary | Complete | Define a small protocol/host contract around the engine session, then implement UCI as the first adapter. UCI parsing, formatting, command lifecycle, `go` limits, `stop`, `isready`, `ucinewgame`, and options stay outside the chess/search core so another protocol such as CECP can be added later without changing engine logic. |
| 7 | Wire DI and CLI composition root | Complete | Register Business, Data, Integrations, protocol adapter, and host dependencies through Microsoft.Extensions.DependencyInjection. Keep `PraxisChessEngine.CLIApp` as the executable composition root and stdin/stdout transport for UCI. |
| 8 | Add transposition support and search ordering | Complete | Add Zobrist hashing, a transposition table, principal-variation tracking, move ordering, killer/history heuristics, and other search optimizations incrementally, protected by correctness tests and benchmarks. |
| 9 | Add opening-book capability | Complete | Replace legacy opening selection with an optional opening-book capability behind a Business contract. Decide later whether its implementation belongs in Data, an embedded resource, or another source; absence/failure must cleanly fall back to normal search. |
| 10 | Add online tablebase capability | Complete | Define an application-facing tablebase probing contract in Business and provider implementations in Integrations. Probe only when a provider supports the current piece count and position; use HTTPS/HttpClientFactory, cancellation, timeouts, explicit unavailable/invalid responses, and automatic fallback to normal search. Start with a modern Syzygy-compatible online provider and allow additional providers later. |
| 11 | Strengthen UCI compatibility | Planned | Exercise the engine against real UCI GUIs and protocol test scenarios. Add protocol transcript tests, timing/cancellation tests, option handling, ponder support if justified, and stable engine identification/version reporting. |
| 12 | Benchmark and tune playing strength | Planned | Add repeatable benchmarks and tactical/position suites. Improve evaluation, pruning, extensions/reductions, time management, and search efficiency based on measured results rather than chess-concept class hierarchies. |
| 13 | Cross-platform packaging | Planned | Validate build/test/publish on supported desktop platforms, including Native AOT viability. Produce straightforward engine binaries that chess GUIs can launch directly. |
| 14 | Retire legacy solution | Planned | Once the new engine reaches functional parity for required behavior and passes compatibility/perft/search validation, remove the root-level legacy projects and solution, migrate any still-useful data/assets, update README documentation, and remove this temporary roadmap. |
